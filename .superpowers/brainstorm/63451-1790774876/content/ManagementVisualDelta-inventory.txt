## 1. Shared primitives — screenshot these first because the changes propagate

### Disabled affordances become substantially more visible
- **Before:** shared `Button` used `disabled:opacity-50`; shared `Tabs` used `disabled:opacity-40`; disabled context-menu rows used `opacity-45`.
- **After:** all three use `opacity-70` (`common/Button.tsx:53`, `Tabs.tsx:58`, `ContextMenu.tsx:142`). This is primitive-wide and changes every disabled control/tab/menu item in the target surfaces.
- **Scenario:** disconnect the sidecar, then open Settings, Agent Hub, Modes, Queue, and Extensions. Capture disabled controls against both light and dark themes; upstream controls look less washed out than base.

### Async state primitive
- `AsyncSection` is new (`common/AsyncSection.tsx:15-114`). It renders:
  - initial loading as centered **vertical** spinner + optional label;
  - hard error with yellow `AlertTriangle`, optional title, message, and Refresh-icon Retry;
  - empty success with `Inbox` icon;
  - stale-data failure as a warning banner above retained children with Retry.
- **Subtle stats-wide delta:** old stats loading put spinner and text horizontally; the shared primitive stacks them vertically. Old stale banner was `mb-3`; new is `m-3`, and Retry gains a Refresh icon (`stats/shared.tsx:23-40`).
- **Scenario:** Stats with delayed response, hard 500, empty range, then successful data followed by failed refresh. Also Model Roles with the same four fixtures.

### Context menu behavior and motion
- **Before:** menu appeared without `omp-pop-in`; Escape could bubble to a dialog behind it; disabled rows were dimmer.
- **After:** `omp-pop-in`, 70% disabled opacity, IME-aware key handling, and `stopPropagation()` on Escape (`ContextMenu.tsx:67-75,107-145`).
- **Scenario:** open any row context menu inside a window, record opening animation, then press Escape. Only the menu should close upstream; the underlying window stays open. Start IME composition and verify Escape does not incorrectly dismiss.

## 3. Settings content surfaces

### Model Roles (`/model-roles` / command palette Model Roles)
- **Before:** each role had a plain native `<select>` populated with every available model; loading was spinner-only; empty was a bordered text box.
- **After:** each role gets a custom combobox/listbox with ChevronDown, focused Search input, outside-click close, Arrow/Home/End navigation, grouped eligible candidates, model display name plus `provider/id`, and a preserved **“{model} (saved)”** option when the saved assignment is absent from candidates (`ModelRolesWindow.tsx` new 47-280).
- Roles are split under **Chat roles** and **Specialized roles** headings; candidates are grouped as Chat, Tiny, Image, Speech (TTS), Transcription (STT), Search, Judge. A role without candidates shows **“No eligible models for this role.”** (`ModelRolesWindow.tsx` new 378-406; locale keys `modelRoles.section.*`, `kind.*`, `noCandidates`).
- Uses AsyncSection: **Could not load model roles**, stale banner **Showing the last roles that loaded successfully**, retry, distinct empty state. Disconnected picker/Refresh is disabled with **Sidecar not connected**.
- **Seed:** chat role with two chat candidates; TTS role with one candidate; search role with none; one saved legacy model not in candidates. Open the chat picker and type a provider substring. Separately fail refresh after rows load.

### Model Compare (`/model-compare`)
- **Before:** every noncurrent row had pointer/hover treatment and could be selected through the whole row/Use button, even if provider was disabled or definitely unauthenticated.
- **After:** blocked rows use `cursor-not-allowed opacity-60`, lose hover, ignore assignment, disable **Use**, and expose exact tooltip:

  - **“Provider is disabled — enable it in Providers first”**.
  Unknown authentication remains selectable rather than being treated as signed out (`ModelCompare.tsx:518-539,610-643`; reason logic new 146-154).
- Role selector, Use, and Refresh also lock while disconnected with **Not connected** title (`ModelCompare.tsx:612-638,696-705`).
- **Seed:** current model; enabled authenticated model; enabled unauthenticated model; disabled model; model whose provider is absent from provider metadata. Capture row opacity/cursors/tooltips and Use states.

### Providers (`/providers`)
- **Truthful states:** hard-load error now says **Could not load the provider list**; failed refresh with retained rows says **Showing the last providers that loaded successfully**; provider discovery failures remain separate; refresh-pending banner gains a small spinner (`ProvidersWindow.tsx:347-383`). ## 7. Formatting/internal-only classification and exclusions

- **No included production file is wholly formatting-only.** Every included changed production file either changes rendering, visible data, motion, keyboard/focus behavior, or availability states.
- Large hunks that are **internal/reindent-only within otherwise visual files**:
  - `PluginDetailDrawer.tsx`: most removed/re-added JSX is fieldset wrapping/indentation; visual deltas are only stale banner/retry, disconnected lock, and slide motion.
  - `QueuePanel.tsx`: optimistic mutation-helper replacement is internal; visual deltas are disconnected banner and disabled actions.
  - `ModelCompare.tsx`, `ModelValueSelect.tsx`, `ProvidersWindow.tsx`, `UsageWindow.tsx`: store/catalog ownership rewiring is internal except where it changes stale/current rows, blocked affordances, refresh results, countdowns, or tallies listed above.
  - `stats/shared.tsx`: extraction to AsyncSection is architectural, but not formatting-only because loading orientation/banner spacing/retry icon change.
  - `common/index.ts`, `settings-window-model.ts`, `agent-hub-settings.ts`: export/helper plumbing only; they enable the rendered behavior documented with their callers.
  - Tests (`*.test.tsx`, `locales.test.ts`) are non-rendering evidence and require no approval frame.
- **Explicitly excluded by assignment:** `common/ConfirmDialog.tsx`, `common/Modal.tsx`; `settings/ProviderConfigDialog.tsx`; `panels/mcp/McpServerWizard.tsx`; `panels/pr/PrCreateDialog.tsx`; `panels/SubagentTranscript.tsx`. Their callers may mention that a flow now continues into a confirmation, but the dialog visuals themselves are not classified here.
- **Remaining unclassified included paths: none.**
